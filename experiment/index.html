统一执行路径

一次选择生成一个环境动作。

每种方法按自己的观测权限从公共候选中作出选择。公共 action adapter 将选择转换为 maholosuite 内置 OSC_POSE 控制器接受的数值 action；runner 把该 raw action 传给 env.step()，再由 evaluator 判断结果。

0101 · 观测

重置配置好的任务实例并读取状态。

0202 · 候选

生成公共 skills、incremental 或 hierarchical 候选。

0303 · 选择

Rules、LLM、VLM、Jev 或 VLA 从公共候选菜单中选择。

0404 · 执行

公共 adapter 按 action_spec 校验归一化 OSC_POSE action，并将同一数值数组传给 env.step()。

0505 · 评估

使用环境 evaluator，并保存决策与状态转移证据。

决策方法

五种策略共用同一动作契约。

方法的差异在于候选选择方式和可见观测。它们不各自创建环境、控制器或成功判定。

01 / 人工配置的顺序

Rules

按预先配置的 L1 skills sequence 执行当前阶段，并选择 direct 候选。Task instance 会逐实例显示物理臂角色。

02 / 结构化状态 → 候选

LLM

读取 runner 提供的结构化文本状态，并从公共候选菜单选择。

03 / 图像 + 状态 → 候选

VLM

结合配置的相机图像和允许的状态字段，返回一个候选选择。

04 / Gateway agent → 候选

Jev

通过 Jev bridge 从同一候选菜单中选择；Gateway 请求尝试与有效响应分别记录。

05 / 图像 + 本体状态 → 候选

VLA

结合任务 prompt、配置的相机图像、本体状态、允许的状态字段和公共候选菜单，返回候选选择；公共 adapter 再生成最终 OSC_POSE action。

五种方法最终都使用 maholosuite 内置的固定阻抗 OSC_POSE 控制器。raw action 指经 env.action_spec 校验后实际传给 env.step() 的完整归一化数值数组；action.csv 原样记录它。单臂布局为 [Δx, Δy, Δz, Δrx, Δry, Δrz, gripper]，前 6 项按 OSC_POSE 输入范围归一化；多臂数组按 env.action_dim 和控制器的 arm slice 组合。

公共候选模式

三种表达下一步动作的方式。

LLM、VLM、Jev、VLA 支持三种模式；Rules 只执行配置好的 skills sequence。

skills · 物理阶段目录

每个当前可用阶段有 {phase}_direct、{phase}_gentle、{phase}_hold 三个候选（例如 approach_direct、grasp_direct）。可用性由目标几何和物理状态决定。Rules 按配置顺序推进，并选择当前阶段的 direct 候选。gentle 朝目标走有界小步（最大位置坐标分量 12 mm、姿态误差修正一半）；hold 保持当前位姿并重新观测。

Skill具体动作
approach末端移动到配置的 approach / goal 位姿；不会自动抬高，夹爪状态不变。
descend移动到配置的 descend 位姿；未提供时使用 goal 位姿。使用任务为 descend 配置的夹爪动作（如果有）。
grasp在当前位置闭合活动夹爪；接近和对准抓取点由前面的 approach 完成。
lift抓住物体后垂直抬升至配置的 lift 高度；未配置时使用 travel 高度。保持闭爪。
carry保持抓持；若高度不足先抬至 travel clearance，再按当前抓持变换将物体移向目的地。保持闭爪。
lower按物体目的地和当前抓持变换，将已抓物体下降到放置位姿。保持闭爪。
release在当前位置 / 目的位置张开活动夹爪。
withdraw移动回注册的 standby 位，并张开夹爪。
rotate在注册操作点保持闭爪接触，绕配置的关节轴朝目标关节角旋转。保持闭爪。
open抓住注册把手，沿铰链圆弧向 open 关节目标移动；要求把手接触与铰链几何已对齐。
close抓住注册把手，沿铰链圆弧向 close 关节目标移动；要求把手接触与铰链几何已对齐。
finish任务 evaluator 判定成功后的安全保持标记；它不属于预定义的 L1 阶段序列。

例子 · L1.lift（代码 task ID：L1.lift_object）的 Rules sequence

步骤Skill动作
01 · approach末端移动至目标物体注册的接近 / 抓取位姿。
02 · grasp在该位姿闭合夹爪，建立抓持。
03 · lift保持闭爪，将物体垂直抬升到配置的 lift / travel 高度。

sequence.py 中该任务的精确顺序是 approach → grasp → lift。Task instance 只在 evaluator 成功后追加 finish；实际使用哪条手臂由该 instance 的分配决定。

incremental · 实际候选菜单

所有选项都以当前末端位姿为基准，每次只改一个维度。平移和旋转不会改变夹爪；它不会先选择任务阶段或自动朝任务目标移动。

类别可选值动作效果
平移 · 18 项X/Y/Z × 正/负方向 × 40/10/2 mm，例如 x_pos_40、z_neg_2。只改变一个世界坐标位置轴；姿态和夹爪不变。
旋转 · 18 项（Roll / Pitch / Yaw）Rx（Roll，世界 X）· Ry（Pitch，世界 Y）· Rz（Yaw，世界 Z）；每轴均有 ±20°、±5°、±1°，例如 rx_pos_20deg。只改变姿态；位置和夹爪不变。
夹爪 · 3 项open · close · hold当前位置张开、闭合，或保持当前位姿和夹爪状态。

数量合计：18 个平移 + 18 个旋转 + 3 个夹爪 = 每条手臂 39 项。双臂环境会把候选标为 left: / right:。

hierarchical · 连续两次选择

策略在一个外层决策里回答两个不同问题：先确定要推进哪个物理目标，再确定针对它执行哪一个位姿动作。

  1. 01 · 选择子目标和手臂

    从活动手臂当前可用的阶段中选一个，例如 approach、grasp、carry、rotate、open、close。目标几何、接触、抓持和关节状态会过滤菜单；它不是固定的 Rules sequence。

  2. 02 · 选择位姿动作

    针对所选阶段和手臂，从下面的阶段专属候选中选一项。夹爪命令继承自阶段，因此第二段不是另一个独立的 open / close 选择。

第二段候选 · 每个已选阶段 26 项

候选组数量具体选项
朝目标移动1{phase}_toward：朝阶段目标走一步，最大位置坐标分量不超过 12 mm，姿态误差每分量最多修正 0.1 rad。
轴向平移6{phase}_x/y/z_pos/neg：一次沿一个轴移动，步长限制在 2–12 mm。
轴向旋转18{phase}_rx/ry/rz_{pos/neg}_{20/5/1}deg：绕世界 X/Y/Z 轴（roll/pitch/yaw）选一个方向和角度。
保持1{phase}_hold：保持当前位姿，同时执行所选阶段带来的夹爪命令。

例：第一段选 grasp，第二段可选 grasp_toward、grasp_x_pos、grasp_ry_neg_5deg、grasp_hold 等 26 项之一。两段选择合成一个目标和一个环境动作；默认 action-repeat=1 时执行一次 env.step()，然后重新观测。

运行闭环

先运行本地 Rules，或做一次 dry-run 冒烟检查。

使用已安装 maholosuite 与实验依赖的 MuJoCo Python 环境。默认 action-repeat 为 1，即每次决策对应一次环境 step。

Rules · L1 skills sequence

PY=/Users/dddogwang/miniforge3/envs/mujoco_env/bin/python
$PY -m experiment.scripts.common.run_method \
  --method rules --mode skills --task-id L1.reach_target \
  --task-instance Pipette004 --max-decisions 80

VLA · 本地 dry-run

PY=/Users/dddogwang/miniforge3/envs/mujoco_env/bin/python
$PY -m experiment.scripts.common.run_method \
  --method vla --dry-run --mode skills --task-id L1.reach_target \
  --task-instance Pipette004 --max-decisions 1

VLA dry-run 只验证本地候选与 OSC_POSE action 管线，不会调用 provider，也不计作模型实验结果。

运行产物

将任务结果和执行证据放在同一局记录中。

summary.json

任务结果、evaluator 有效性、决策/step 数及本局错误。

decisions.jsonl

候选菜单、选中的 ID、策略阶段及逐次决策记录。

transitions.jsonl

环境 step 前后的状态与任务 evaluator 变化。

provider_calls.jsonl

观测权限、模型或 Gateway 请求尝试数、有效响应数。

action.csv · images/ · videos/

实际传给 env.step() 的 raw OSC_POSE 数值数组、保存的相机帧和可选的逐相机录像。

比较与证据

记录固定条件，也记录每种方法实际看到的内容。

  • 每组比较固定并记录任务、instance、reset 状态、seed、控制器、候选模式和 evaluator。
  • 各方法的观测权限不同：Rules 读取公共物理状态；LLM 与 Jev 接收结构化文本；VLM 接收配置图像和允许的状态字段；VLA 接收任务 prompt、配置图像、本体状态、允许的状态字段和公共候选菜单。报告中应保留这些差异。
  • 以环境 task_success 作为结果，并单独保留 task_evaluation_valid；evaluator 异常不能算作普通任务失败。
  • dry-run、一次模型请求或单个 instance 成功，只能说明对应的有限路径；不能证明更广任务覆盖或真实机器人成功。
  • 当前共享实验 runner 只接受 L1 任务。L2–L4 仿真工作流仍是任务定义，不是已经完成的方法比较结果。
