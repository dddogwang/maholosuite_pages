Task

Task contracts for skills, workflows, and protocols.

L1

原子能力

到达 · 抓取 · 释放 · 搬运 · 放置 · 按压 · 旋转 · 打开 · 关闭 · 保持

L2

组合工作流

打开 → 转移 → 操作 → 复位，并显式记录前置条件和事实。

L3

跨设备工作流

通过显式确认、恢复策略和安全停止连接对象与设备。

L4

协议状态

记录样本、谱系、位置、吸头、请求条件和符号体积。

L1.grasp_object
抓取移液器、试管或 Opener。闭合 Maholo 夹爪抓住 {object}，并保持稳定抓取。
指腹接触被判定为抓取成功。仅模型
L1.release_object
释放已抓取对象。在 {destination} 释放 {object}。
对象曾被抓取、当前已释放，并满足配置的目标位置条件。仅模型
L1.transport_object
搬运已抓取对象。保持稳定抓取，将 {object} 搬运到 {destination}。
对象保持抓取状态，并到达目标位置或满足最小位移。仅模型
L1.place_object
放置对象。将 {object} 移动到 {destination}，对齐后释放。
满足目标位姿，并且对象已经释放。仅模型
L1.insert_or_remove_object
将对象插入槽位或从槽位取出。在 {slot} 对 {object} 执行配置的 {operation} 操作。
满足插入/取出位移，以及抓取/释放条件。仅模型
L1.press_control
按压设备控制件。移动到 {target} 的 {joint} 控制件并按压。
配置的关节到达目标位置。仅模型
L1.rotate_control
旋转旋钮或锁扣。将 {target} 的 {joint} 控制件旋转到配置的目标角度。
配置的关节到达目标角度。仅模型
L1.open_articulated_part
打开门、盖子或其他可动部件。将 {target} 的可动 {joint} 驱动到打开目标。
关节到达打开目标。仅模型
L1.close_articulated_part
关闭门、盖子或其他可动部件。将 {target} 的可动 {joint} 驱动到关闭目标。
关节到达关闭目标。仅模型
L1.hold_and_operate
在指定时间内保持接触、抓取或目标位姿。在 {target} 上维持配置的 {condition}，持续 {hold_steps} 个保持步数。
条件持续满足规定步数。仅模型

环境示例

以数据形式实例化基准。

Level 1 选择能力与目标实例；Level 2 组合显式阶段；Level 3 用确认和恢复策略协调跨对象、跨设备操作；Level 4 记录协议状态、样本谱系、吸头、请求条件和符号体积，但不宣称物理结果。

Python
import numpy as np
from robosuite.environments.manipulation.maholoLevel1Env import MaholoLevel1Single

env = MaholoLevel1Single(
    robots="MaholoRight",
    task_id="L1.grasp_object",
    target_instance="Tube008",
    target_config={"position_tolerance": 0.05},
    use_camera_obs=False,
    use_object_obs=True,
    has_renderer=False,
    has_offscreen_renderer=False,
    renderer="mujoco",
    horizon=1000,
)
obs = env.reset()
obs, reward, done, info = env.step(np.zeros(env.action_dim))
env.close()

L1 参数

task_id、target_instance、target_config 和 active_arm 决定目标解析结果与成功判定。

L2 参数

workflow_id、parameters、stage_configs、initial_facts 和 initial_symbolic_state 定义有序工作流。

L3 参数

`workflow_id`、组件确认、阶段事实、恢复策略和安全停止记录定义跨设备协调。

L4 参数

`protocol_id`、样本谱系、位置、吸头历史、请求条件、协议时间和符号体积定义协议账本。

通用控制项

实验需要记录 `robots`、控制器配置、horizon、渲染开关、相机/对象观测和奖励设置。

RL 契约

奖励、观测与终止。

比较策略前，基准使用者应检查这三个接口。

01

奖励设计

注册表环境将结果归一化为成功、失败、阶段完成和可选的进度塑形；旧版设备任务还会塑形接近距离和关节角变化。

rₜ = success | stage bonus | progress − penalties
02

观测接口

从机器人本体感知和可选相机输入开始；L1 增加相对目标误差，L2 增加阶段与事实，L3 增加跨设备阶段账本，L4 增加协议状态和符号样本记录。

oₜ = robot + camera? + task state
03

回合边界

成功或失败可以结束回合，否则使用配置的 horizon；当前置条件不满足时，工作流阶段可以中止。

done = success ∨ abort ∨ horizon

_post_action 返回值

奖励族

结合任务语义阅读奖励塑形。

L1 注册表

成功 +1.0；终止失败 −1.0；未完成步骤在 reward_shaping=True 时使用 result.progress。

success_reward、failure_penalty、action_penalty_scale 和 reward_scale 可配置；默认动作惩罚为 0。
L2 工作流

工作流成功 +1.0；原子阶段完成 +0.25；中止/失败 −1.0；开启塑形时，未完成阶段使用 progress。

normalize_stage_reward 可按阶段数归一化中间奖励；可重试的最终状态缺失返回 0。
L3 工作流

记录跨设备阶段确认和最终事实；不会从事件推断物理转移已经发生。

Level3WorkflowExecutor 显式保留恢复与安全停止结果。
L4 协议

有序协议完成是符号状态；体积账本更新是守恒的符号记录。

ProtocolExecutor 在存在明确证据前保持 physical_outcome_available=false。
旧版设备任务

现有开门/开盖和移动/抓取环境会塑形到达距离与关节角变化，再叠加成功奖励。

这些任务类有独立尺度；记录配置后再与归一化的 L1/L2 注册表比较。
基准注意事项。

“仅几何”表示策略可以在到达、接触和放置判定上评估；不表示液体、温度、混合、污染或生物学结果已经被仿真。
